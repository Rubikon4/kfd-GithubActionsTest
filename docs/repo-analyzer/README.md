# Анализатор репозитория

Программа принимает путь к каталогу и выводит два отчёта: число файлов и строк по расширениям и три самых длинных файла.

Обрабатываются `.kt`, `.kts` и `.md`. Каталоги `.git`, `.gradle`, `build` и символические ссылки пропускаются.

## Этапы работы

[Монолит](https://github.com/Rubikon4/kfd-GithubActionsTest/commit/98e926b956fde773edd824cc7a9626053c79dd31) — оба отчёта реализованы в одном модуле `:app`.

Модули — анализатор разделён на `:core` и `:cli`.

## Структура проекта

- `:core` — обход файлов, подсчёт строк, сортировка и тесты расчётов.
- `:cli` — точка входа, аргументы, вывод отчётов, код завершения и тесты CLI.
- `:app` — исходные функции и тесты практики «Инженерный контур».

Модуль `:cli` зависит от `:core`, потому что использует результаты анализа для вывода отчётов. Модуль `:core` не зависит от CLI: расчёты и их тесты можно запускать отдельно.

Внешние зависимости подключены через существующий каталог версий `gradle/libs.versions.toml`.

## Запуск

Нужен JDK 25. Если Java не настроена в терминале, перед запуском укажите путь к JDK 25 в `JAVA_HOME`.

Из корня проекта в Bash:

```bash
./gradlew :cli:run --quiet --args='"/полный/путь/к/каталогу"'
```

Путь передаётся одним аргументом. Для отсутствующего пути или пути к файлу программа выводит сообщение в stderr и завершается с кодом 1.

## Пример из четырёх файлов

Создайте временный каталог и запустите анализатор:

```bash
sample=$(mktemp -d)
mkdir "$sample/src"
printf 'package sample\nclass A' > "$sample/src/A.kt"
printf 'package sample\nclass B\n' > "$sample/src/B.kt"
printf '' > "$sample/README.md"
printf 'ignored' > "$sample/notes.txt"
./gradlew :cli:run --quiet --args="$sample"
```

Результат:

```text
По расширениям:
kt: 2 files, 4 lines
md: 1 file, 0 lines

Самые длинные файлы:
src/A.kt: 2 lines
src/B.kt: 2 lines
README.md: 0 lines
```

В `A.kt` нет завершающего перевода строки, в `B.kt` он есть. Оба файла содержат по две строки. Пустой `README.md` содержит ноль строк. `notes.txt` не учитывается.

Расширения отсортированы по алфавиту. Самые длинные файлы отсортированы по убыванию числа строк, при равенстве — по относительному пути. Если файлов меньше трёх, выводятся все. В пустом каталоге под заголовками нет записей.

## Проверки

Сборка и тесты всего проекта:

```bash
./gradlew build --console=plain
```

Тесты расчётов отдельно, без запуска CLI:

```bash
./gradlew :core:test --console=plain
```

После переноса сохранены те же 32 теста: 14 исходных в `:app`, 12 тестов расчётов в `:core` и 6 тестов CLI в `:cli`. Все тесты проходят.

Проверяются оба отчёта на примере из условий, пустой каталог, неправильный путь, расширение `.kts`, исключённые каталоги, символические ссылки, сортировка и ограничение в три файла.

До переноса сохранены вывод и коды завершения монолита. После переноса выполнены те же шесть сценариев: пример из четырёх файлов, пустой каталог, отсутствующий путь, файл вместо каталога, отсутствие аргумента и лишний аргумент. Вывод в stdout и stderr и коды завершения совпали.
